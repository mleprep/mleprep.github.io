# leetcode_review

A concise, browsable interview-prep site: **https://mleprep.github.io/**

| Section | What's inside |
|---|---|
| **Algorithms** | **249 problems** (47 Easy / 169 Medium / 33 Hard) from Blind 75, NeetCode 150, Grind 169 and LeetCode Top Interview 150, grouped into 19 patterns. Each has the key idea, an ASCII sketch, complexity, **Python + Java** solutions with tests, and related-problem links. |
| **System Design** | Interview framework & estimation numbers, 16 building blocks (caching, sharding, consistent hashing, CAP, queues, rate limiting, LSM vs B-tree, IDs, idempotency…), 15 classic designs (URL shortener, news feed, chat, Uber, YouTube, Dropbox, Kafka, payments…). |
| **ML / Deep Learning** | ML fundamentals Q&A, deep learning, LLMs & GenAI (RLHF/DPO, LoRA, RAG, KV cache…), 10 NumPy implementations from scratch (attention, MLP backprop, k-means, AUC…), ML system design (recsys, search, ads, fraud, A/B testing). |

Progress checkboxes are saved in your browser. Press `/` to search; filter by difficulty or "Todo"; "Random problem" picks an unsolved one.

**Algorithm topics:** Arrays & Hashing · Two Pointers · Sliding Window · Stack & Monotonic Stack · Binary Search · Linked List · Trees · Tries · Heap · Backtracking · Graphs · Advanced Graphs (Dijkstra, Bellman-Ford, MST, Tarjan, Hierholzer) · 1-D DP · 2-D DP · Greedy · Intervals · Math & Geometry · Bit Manipulation · Design.

## Run solutions locally

Every problem is also generated as a standalone runnable file with tests:

```bash
cd python && python 0001_two_sum.py          # prints OK when all asserts pass
cd java   && java P0001TwoSum.java            # Java 11+ single-file launch, prints OK
```

The `Solution` class inside each file is exactly what you paste into LeetCode. Python files import `python/lc.py`
(ListNode / TreeNode + `make_list`, `list_vals`, `make_tree`, `tree_vals`, `find_node`); Java files inline the same helpers
(`ListNode.of(1, 2, 3)`, `TreeNode.of(3, 9, 20, null, null, 15, 7)`).

## Repo layout

```
content/                 <- source of truth (markdown, one file per topic)
  dsa/NN-topic.md            problems: idea + ```viz + ```python / ```java (each with a "# test" / "// test" part)
  system-design/*.md         articles (one "## " heading per article)
  ml/*.md                    articles
build.py                 <- content -> data/*.json (site) + python/*.py + java/*.java (runnable)
index.html, assets/      <- static single-page site (no build tools; marked + highlight.js from CDN)
data/, python/, java/    <- generated by build.py (committed so GitHub Pages and local runs just work)
```

## Edit or add content

1. Edit `content/dsa/<topic>.md` (the problem format is documented at the top of `build.py`).
2. `python build.py --test` regenerates everything and runs **all 498 Python + Java test files** in parallel
   (Java needs `java` on PATH or `JAVA_HOME`). Add problem numbers to test only those: `python build.py --test 1 146`.
3. Preview: `python -m http.server` and open http://localhost:8000.
4. Commit and push to `main`; GitHub Pages serves the repo root.
